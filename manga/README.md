# 手描き漫画文庫

`tegaki/`（手描き挿絵文庫）をもとに、スクロールを止めた場面を **1 ページの漫画（2〜4 コマ）** にする別サイト。
読み方・場面の判定（場所・時間帯・人物・セリフの話し手）・中継・キャッシュは手描き挿絵文庫と同じで、
違うのは「場面の見せ方」：1 枚の絵の代わりに、コマ割り・カメラ・背景効果・縦書きの吹き出しのある漫画のページを描く。

漫画ページの作り方は、移植セット（オートコミックエンジンのプロンプト生成方式と Jevアシスト）の仕様に沿っている。

- コマの中の絵は、手描き挿絵文庫と同じ `draw.js` の手描き（画像生成はしない）。線が 1 秒に 8 回ふるえる
- 同じページを画像生成モデルで描き直したいときは、読書画面の「プロンプト」から、ページプロンプト（英語・移植セットの型と固定ルールのまま）をコピーできる

## 開き方

```bash
cd manga
python3 -m http.server 8000    # → http://localhost:8000/
```

## 場面 → 漫画のページ（`manga.js`）

1. **コマ割り**（`Manga.split`）：本文から、導入（状況説明・引きの絵）→ 会話 → 締め（寄り）のコマを作る。目安 3〜4 コマ、短い場面は 2 コマ
   - セリフは本文のまま。1 コマ 2 つまで。多いときは続くセリフを 2 つずつまとめ、4 コマに収める
   - 導入のコマは、場面の最初の地の文をナレーション（白い四角枠・縦書き）にする。長ければ枠に入る長さで切る
   - セリフのない場面は、導入（引き）→（長ければ動作）→ 締め（寄り）
2. **Jevアシスト判定**：コマ割りは本文だけで決まるので、コマの質問を場面判定と **同じ 1 回の問い合わせ** に束ねる（state に `panels` を足す）
   - `role_N`（Choice・8 項目）：状況説明・会話・反応・感情の山場・決意・転機・動作・締め・ヒキ・日常
   - `intensity_N`（Score・0〜2）：人物のいるコマの中心人物の感情の強さ（弱い／中くらい／強い）
   - `key_panel`（Choice）：ページで最も重要なコマ（枠を太くする）
   - 強さが **1.0 以上** のコマがあれば、2 回目の問い合わせで `emotion_N`（Choice・23 項目）を聞く。設定で止められる（Jev の呼び出しが 1 回減る）
   - 2 動作・コメディの判定は、簡易版では使い道がないので聞いていない
3. **判定 → 演出**（`Manga.assist`）：移植セット 03 の対応表と閾値をそのまま実装
   - カメラは感情に付ける。感情が判定できたコマは感情 → カメラ（威圧ならローアングル、悲しみなら俯瞰、驚きなら顔の寄り…）、感情のないコマだけ役割で補う（状況説明＝引き、動作＝動きに沿った角度、日常＝ややロング）
   - 会話・反応はプールから回し、直前と同じ系統を続けない
   - 確信度 0.35 未満ではカメラを付けない。不安のダッチアングルは強さが「強い」ときだけ
   - 背景効果は感情が強いコマだけ：キラキラ・オーラ・花・トーン・集中線・流線・白ドット
   - 手描きの絵では、カメラを「ズーム・傾き・縦の伸び縮み・顔を置く位置」で表す（例：ローアングルは縦に少し伸ばして見上げる、俯瞰は縮めて人物を下に置く）
4. **レイアウト**：移植セット 02 のレイアウト表（full_page・2comma・3comma・4comma・T4-G）。読む順は右上から。穏やかな 4 コマは T4-G、緊張した 4 コマは 4comma
5. **ページプロンプト**（`Manga.prompt`）：02 の構成順（冒頭 → 読み順 → 画風 → 白フチ → ページ形式 → レイアウト → 背景 → キャラ注記 → コマごと → 固定ルール）。固定ルールの英語は言い換えていない
   - 参照画像は使わないので、背景は「場所の説明文が正」の書き方にしている
   - 簡易キャラ表：人物の見た目の種類（成人女性・少年…）× 時代 で決まる文。同じ作品なら場面をまたいで同じ文になる
   - 画風（スタイル行）は 4 つの候補から選ぶ（既定は手描きの絵に近い「簡易カラー」）。作品全体でそろえる

## 読書画面

- スマホを縦に持つと上の約 6 割に漫画のページ、下に本文。横向きや PC では左にページ、右に本文（手描き挿絵文庫の「絵を背景にする」表示はない）
- ページが替わるときは、前のページを薄くしながら、新しいページのコマを読む順に出す。章が変わると一度暗転
- 「プロンプト」：いまのページの Jevアシストの判定（コマごとの役割・強さ・感情 → カメラ・効果）と、ページプロンプト
- デバッグ表示（D キー）に、ページのレイアウトとコマごとの判定も出る

## Netlify に置く（既存の 2 つのサイトとは別のサイト）

同じリポジトリから、もう 1 つサイトを作る。中継関数（`../netlify/functions`）はビルドのときにコピーして使う。

1. https://app.netlify.com/ で **Add new project → Import an existing project → GitHub** → `jev_visualnovel`
2. **Base directory** に `manga` と入れる（Build command・Publish directory は `manga/netlify.toml` から自動で入る）→ **Deploy**
3. **Project configuration → Environment variables** に、既存のサイトと同じ `TYPESAFE_API_KEY`・`RELAY_PASSPHRASE`（必要なら `RELAY_PUBLIC_UNTIL`・`RELAY_DAILY_LIMIT`）を入れて再デプロイ

`manga/` だけを変えたときは、このサイトだけがデプロイされる（既存の 2 つは変わらない）。`netlify/functions/` を変えると 3 つともデプロイされる。
一般公開の回数（`RELAY_DAILY_LIMIT`）はサイトごとに数える。感情の細目を聞く場面では 1 場面で 2 回数える。

## 動作確認

```bash
cd manga
for t in step1 step2 step4 step5 reading stage era manga; do node tests/$t.test.mjs; done
```

- `manga.test.mjs`：コマ割り、Jevアシストの質問票、判定 → カメラ・効果の対応表と閾値、レイアウト（コマがページに収まる・重ならない・右上から読む順）、吹き出し（コマの中に収まる・禁則・しっぽ）、ページプロンプトの構成順と固定ルール、全カメラ × 全効果の描画
- `stage.test.mjs`：場面判定の質問とモック、発火ロジック、手描きの部品すべての描画、サンプルを通して読んだときのページ（レイアウト・暗転・場所・雪・コマの出る順・プロンプトの画面）
- ほかは手描き挿絵文庫と同じ（読み込み・停止検知・キャッシュ・設定・時代の判定し直し）
