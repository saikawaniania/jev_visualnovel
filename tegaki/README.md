# 手描き挿絵文庫

`viewer/`（青空文庫サウンドノベル化ビューア）の絵を、写真風の画像とシルエットから **手描きアニメ** に作り直した別サイト。
読み方・Jev の判定・中継・キャッシュは `viewer/` と同じで、違うのは「絵の描き方」だけ。

- 背景・人物・天候・心象を、`tegaki.js` で canvas に毎コマ描く。線が 1 秒に 12 回ふるえる（手描きアニメの「線の震え」）
- 画像素材は使わない（`assets/` も `manifest.json` も要らない）
- `preview.html`：部品の見本。場所・時間帯・時代・人物・姿勢・表情・天候・心象を選んで確かめられる

## 開き方

```bash
cd tegaki
python3 -m http.server 8000    # → http://localhost:8000/   見本は http://localhost:8000/preview.html
```

## 吹き出し

セリフがある単位では、場面の判定に質問を足す（セリフがない単位では聞かない）。

| 質問 | 型 | 中身 |
| --- | --- | --- |
| `line` | Choice | 候補のセリフから、場面をいちばんよく表す一言。候補が1つなら聞かない |
| `speaker_1` … `speaker_4` | Choice | 候補のセリフごとの話し手の見た目：語り手・成人男性・成人女性・少年・少女・老人（男）・老人（女）・場面にいない人物・不明 |
| `line_importance` | Score | さりげない・ふつう・物語の要 |

- 候補のセリフ：行の頭から始まる「」と『』（地の文の中の名前や題名は除く）。5つ以上あれば、！？・長さ・単位の最後のほうを優先して4つまで
- 話し手はセリフごとに聞く。Jev は1回の問い合わせの質問を別々に評価するので、「代表のセリフを言った人」と聞くと、どのセリフか分からないまま答えてしまうため
- 話し手の質問には、そのセリフの直前・直後の地の文（「と少女が言った」など）を添え、会話が交互に進むこと・言葉づかい・『』は通知や手紙であることを手がかりにするよう指示する
- 答えの見た目を、描いている人物に当てはめる。語り手は主人公の見た目に置き換える。描いている2人のどちらとも合わなければ、画面にいない人のセリフとして扱う
- 重要度が「さりげない」寄り（0.25 未満）なら出さない。「物語の要」は文字を太く大きく、外側に勢いの線を描く
- 縦書きが話し手の頭の上か横に収まれば縦書き（4列まで）、収まらなければ横書き。縦書きでは長音・括弧・英数字を90度回し、句読点と小さい仮名は右上に寄せる
- しっぽは話している人の頭へ向ける。場面にいない人物のセリフは左上から出て、しっぽは画面の外へ
- 人物が出そろってから出す。設定の「セリフを吹き出しで出す」で消せる

## 試し読み

`samples/` のうち、起動画面の「試しに読む」に出すのは次の5作品（「雨の停車場」と書き下ろし4作品）。「海辺の喫茶店」「森の道」はファイルだけ残している（読み込みのテストで使う）。書き下ろしはどれも短い。

- `shuden_no_ato.txt`「終電のあとで」：現代劇。終電を逃した夜、駅のベンチで拾ったスマホに「明日の私」から通知が届く
- `ryu_no_yubinya.md`「竜の郵便屋」：ファンタジー。見習い郵便屋の少女と小さな竜が、「まだ生まれていない王さま」宛ての手紙を森の魔女へ届ける
- `doukutsu_no_kage.md`「洞窟の影」：ファンタジー。騎士が城から雪山を越えて洞窟の魔物と戦い、少女を連れて帰る。城・雪山・洞窟、馬・鳥・モンスター、騎士、歩く・剣を振る・しゃがむ・泣く・抱き合う・走る・手を振る、驚きが出る
- `otera_no_neko.txt`「お寺の猫」：現代劇。お寺の猫を追いかけた少女が、夕暮れの墓地でおばけに出会う。寺・墓地、猫、僧侶・おばけ、しゃがむ・泣く・手を振る、驚きが出る

場面ごとに絵が替わるように、書き下ろしの2作品は段落のまとまりを「◇」で区切っている。

## 画面のデザイン

Anthropic 公式の frontend-design スキル（`.claude/skills/frontend-design/`）の方針で作った。

- 色：和紙（少し青みのある白）に藍墨の文字。山吹色は「読み込む」などの主な操作と、キーボードの焦点だけに使う。ダークテーマは夜の藍の紙
- 書体：見出しだけ手書き風の Yusei Magic、本文は Shippori Mincho B1、操作部品はシステムのゴシック（Google Fonts。読めないときは代わりの書体で出る）
- 起動画面のいちばん上は、サンプルの一文とその場面の手描きの絵を 5 秒ごとに替えて見せる（動きを減らす設定では止まった 1 枚）
- 作品の一覧はカードではなく帳面の罫線の行。絵の上に本文を載せる帯は、テーマに関係なく暗い藍

## `viewer/` から変えたところ

- `JV.Stage` を canvas 版に置き換えた。背景と人物はクロスフェード、天候・心象・緊張感・暗転は数値の補間。人物は別の canvas に描いてから重ねる（半透明のときに線が透けないように）
- `JV.Assets`・`JV.Weather`（画像素材と DOM の雨雪）は削除
- 人物の種類：`老人` を `老人（男）`・`老人（女）` に分けた
- 表情：判定の `emotion`（気持ち）が確信度 0.35 以上なら、その気持ちの顔にする。読み取れなければ、緊張感が高い場面で不安の顔
- 重さ対策：canvas は長辺 1600px まで、止まっているときは 1 秒 12 コマ・フェード中だけ 30 コマ。読書画面以外・演出オフ・タブが裏のときは描かない

## Netlify に置く（既存のビューアとは別のサイト）

同じリポジトリから、もう 1 つサイトを作る。中継関数（`../netlify/functions`）はビルドのときにコピーして使う。

1. https://app.netlify.com/ で **Add new project → Import an existing project → GitHub** → `jev_visualnovel`
2. **Base directory** に `tegaki` と入れる（Build command・Publish directory は `tegaki/netlify.toml` から自動で入る）→ **Deploy**
3. **Project configuration → Environment variables** に、既存のビューアと同じ `TYPESAFE_API_KEY`・`RELAY_PASSPHRASE`（必要なら `RELAY_PUBLIC_UNTIL`・`RELAY_DAILY_LIMIT`）を入れて再デプロイ

一般公開の回数（`RELAY_DAILY_LIMIT`）と停止スイッチは、サイトごとに別々に数える（Netlify Blobs はサイトごと）。

## 動作確認

```bash
cd tegaki
for t in step1 step2 step4 step5 reading stage era; do node tests/$t.test.mjs; done
```

`stage.test.mjs` は、場所 28 種 × 時間帯 × 時代と、人物 13 種（パターンBも）× 姿勢 × 表情 × 時代のすべてを実際に描いてエラーがないことと、サンプルを通して読んだときの演出（暗転・場所替え・雪・群衆・心象・表情）を確かめる。
`era.test.mjs` は、最初の判定で時代が決まらなかった作品を、読み進めてから判定し直す流れ（Jev には新しく読んだ部分の 1,500 字まで、決まらなければキーワードで）を確かめる。
